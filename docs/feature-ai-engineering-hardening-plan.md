## Outcome

Make the AI, signal-entry, configuration, and runtime-lifecycle additions safe
to operate and maintain before release, without redesigning Moonwalker as a
distributed system or changing its accepted trading behavior.

The implementation should leave Moonwalker with:

- supervised critical background work and bounded noncritical AI work;
- one canonical typed configuration contract and explicit migrations;
- strict administrative API payloads and same-origin network defaults;
- typed trade and signal-entry seams rather than raw dictionaries everywhere;
- one AI provider request per required decision;
- bounded, indexed AI analytics;
- rendered frontend and dry-run end-to-end coverage enforced by hardened CI.

## Architecture

### 1. Supervise runtime ownership

Replace the detached task list in `backend/app.py:145-167` with a Litestar
lifespan-owned supervisor using `asyncio.TaskGroup`.

- Treat symbol intake, ticker watching, and housekeeping as critical runtime
  tasks. An unexpected exit fails the lifespan and initiates orderly shutdown.
- Keep replay-candle backfill optional: log its failure with a stack trace and
  continue serving.
- Give every task a stable name and include that name in failure logs.
- Shutdown order: stop accepting new signal work, drain bounded queues, cancel
  long-lived watchers, stop services, close shared HTTP/Redis/DB clients.
- Add an inline ASCII ownership diagram near the lifespan implementation.

### 2. Keep a stable AI facade

Preserve the public functions imported from `backend/service/ai_trust.py`, but
split the 1,570-line module behind that facade:

```text
Orders / persistence / controllers
               |
               v
        ai_trust.py facade
          /      |      \
         v       v       v
 provider.py  calibration.py  analytics.py
 HTTP/model   scoring/buckets  DB queries/cache
         \       |       /
          `-- typed contracts --'
```

The facade owns policy; the provider module owns HTTP; calibration is pure where
possible; analytics owns read models and cache invalidation.

### 3. Default to same-origin

Replace wildcard CORS in `backend/app.py:214-220` with:

- same-origin HTTP and WebSocket access by default;
- an explicit normalized origin allowlist for operators who need another
  dashboard origin;
- startup rejection of malformed/wildcard origins in live mode;
- documented LAN/reverse-proxy examples.

This is transport hardening, not a new authentication system.

### 4. Add one typed signal-entry coordinator

Move the repeated ASAP, SymSignals, and WebSocket sequence into one coordinator:

```text
plugin candidate
  -> normalize symbol/settings
  -> filter + delisting visibility
  -> rank/reserve capacity
  -> resolve strategy + entry size
  -> build typed BuyIntent
  -> Orders.receive_buy_order()
  -> release reservation on every exit
```

Plugins remain responsible for source-specific parsing only. The coordinator
must preserve the existing central delisting and AI enforcement gates in
`Orders`; it must not duplicate them.

## Code Quality and Data Contracts

### Administrative request DTOs

Replace truthy coercion in `backend/controller/config.py:744`, `:812`, and
`:904` with strict Litestar DTOs.

- `confirm` and `restore_trade_data` accept JSON booleans only.
- Strings such as `"false"` and numbers such as `1` return a shaped 400.
- Unknown fields are rejected for destructive/operational mutations.
- Errors remain operator-readable and never echo backup payloads or secrets.

### Canonical configuration contract

Make the backend the source of truth for key, type, default, bounds, enum,
visibility, readiness relevance, and sensitive/redaction metadata.

Migrate in three bounded slices:

1. Recovery DCA fields currently duplicated across backend defaults, DCA
   parsing, controller metadata, frontend load/submit/rules, and readiness.
2. Delisting-protection fields.
3. AI Trust fields.

Generate or serve a versioned frontend-safe schema. Keep secrets write-only and
never serialize credential values into generated artifacts.

### Signal settings persistence

Unify the strict runtime parser in `backend/service/signal_runtime.py:175` and
the permissive controller parser in `backend/controller/config.py:89`.

- Persist canonical sorted JSON matching a typed, versioned schema.
- Accept dictionary input and valid legacy JSON during the migration window.
- Perform a one-time conversion of valid legacy representations.
- Reject malformed or non-object settings with a precise readiness blocker.
- Never silently replace malformed settings with `{}`.

### Trade-mode migration

Add a versioned, idempotent migration for legacy lifecycle keys before removing
the runtime-only fallback in `backend/service/config.py:164-192`.

- Back up the pre-migration values.
- Write canonical `trade_mode` in one transaction.
- Record the migration version.
- Validate startup, config restore, and rollback/retry after interruption.
- Remove fallback aliases only after legacy fixture coverage passes.

### Trading domain contracts

Introduce contracts in stages:

1. `BuyIntent` and `SellIntent` at service boundaries.
2. `ExecutionFill`/`ExecutionResult` at the exchange boundary.
3. Persistence records consumed by `order_persistence`.

Required fields must not remain optional through `total=False` TypedDicts.
Raw CCXT dictionaries are normalized once and do not escape the exchange
adapter. Preserve public controller payload compatibility during the transition.

### External volume normalization

Replace the SymSignals `DirtyFix` at `backend/signals/sym_signals.py:203` with a
typed parser accepting numeric values and documented `k`/`M`/`B` suffixes.
Reject negative, nonfinite, missing-unit ambiguous, and malformed values with a
source-specific reason code.

### Obsolete compatibility cleanup

After call sites and tests use the shared helper module directly, remove the
datetime compatibility re-exports from
`backend/service/autopilot_memory.py:18-22`. Do not combine this cleanup with
behavioral changes.

## AI Performance and Async Design

### Reuse the enforcement evaluation

`backend/service/ai_trust.py:983-1069` already computes the entry decision, but
`backend/service/order_persistence.py:478` schedules another observation which
can call the provider again.

- Return a typed `EntryEvaluation` from enforcement.
- Carry its immutable ID/result through the successful buy result.
- Persist that exact evaluation with the fill.
- Persist blocked evaluations immediately.
- Score shadow-only entries exactly once after a successful fill.
- Make persistence idempotent by evaluation ID and deal/order identity.

### Bound background AI work

Replace `asyncio.create_task()` in `backend/service/ai_trust.py:1539-1570` with
a lifespan-owned worker queue.

- Bounded capacity and configurable worker count.
- Deduplicate by event type plus deal/evaluation ID.
- Entry observations may apply documented backpressure; low-value duplicate
  refreshes may coalesce.
- Outcome attribution is durable/idempotent and must not be silently dropped.
- Drain within a shutdown deadline; retain unfinished durable work for restart.
- Expose queue depth, oldest age, rejected/coalesced count, and last error.
- Add an inline ASCII queue state diagram near the worker implementation.

### Share the Ollama client

Create one lifecycle-managed `httpx.AsyncClient` with explicit connect/read/
write/pool timeouts, bounded connections, and orderly close. Provider retries
must be bounded and limited to safe transient failures; no retry storm.

### Aggregate analytics in the database

Replace sequential counts and the unbounded provider-status row load in
`backend/service/ai_trust.py:1441-1469` with grouped/conditional database
aggregates.

- Add indexes matching status/outcome/created-at query shapes.
- Bound recent/review detail queries.
- Cache the reduced payload by a persisted data revision, not a time-only cache.
- Invalidate after prediction, attribution, calibration, or operator-note writes.
- Establish query-count and p95 latency budgets on a production-shaped fixture.

## Failure-Mode Matrix

| New path | Realistic production failure | Required test | Handling | Operator visibility |
|---|---|---|---|---|
| Task supervisor | watcher exits unexpectedly | integration | fail lifespan, orderly shutdown | fatal task name and reason |
| Optional backfill | corrupt replay row | integration | isolate and continue | warning with repair guidance |
| Admin DTO | `"false"` interpreted as true | unit/API | reject 400 | field-specific message |
| Origin policy | reverse-proxy origin omitted | integration | reject request | startup/docs plus browser error guidance |
| Config schema | generated client lags schema version | unit/integration | compatibility check | readiness blocker |
| Signal settings migration | malformed legacy text | migration fixture | leave source untouched | explicit blocker, no `{}` fallback |
| Trade-mode migration | process stops after partial write | integration | transaction + idempotent retry | migration failure status |
| CCXT normalization | exchange omits required fill field | unit | domain validation/fallback policy | safe order error |
| Signal coordinator | reservation leaks after exception | concurrency test | context-managed release | reason-coded signal log |
| Volume parser | numeric value has ambiguous units | table unit test | reject candidate | source reason code |
| Provider client | Ollama stalls | async integration | bounded timeout/retry | provider unavailable state |
| Evaluation handoff | persistence retries after fill | integration | idempotency key | one persisted evaluation |
| AI queue | burst exceeds capacity | load test | backpressure/coalesce | depth/rejected metrics |
| Shutdown drain | provider is still blocked | integration | deadline + durable retry | unfinished-work warning |
| Analytics | table grows to production size | query-count/latency | indexed aggregate + bound | degraded status/log |
| Mobile UI | narrow viewport clips status text | Playwright | responsive wrap/layout | visible complete text |

Every row receives a test and an explicit handling/visibility policy in this
plan. Four current silent or weakly visible gaps—critical task exits, permissive
admin booleans, malformed signal-settings fallback, and unenforced CI—are P1
work; none remains intentionally unresolved.

## Phased Implementation

### Phase 0 — Establish enforcement

1. Record backend coverage and frontend characterization baselines.
2. Add Vitest/Vue Test Utils and a minimal Playwright dry-run harness.
3. Harden `scripts/ci.sh` so missing Node/npm is a clear prerequisite failure.
4. Add the SHA-pinned, least-privilege required CI workflow.
5. Add legacy database, backup, provider, and production-shaped analytics
   fixtures before refactoring their paths.

Exit gate: the required workflow executes backend, frontend, build, type, lint,
coverage, and dry-run E2E checks without secrets.

### Phase 1 — Close unsafe API and migration seams

1. Add strict administrative DTOs.
2. Implement same-origin default plus explicit origin allowlist.
3. Add the versioned migration framework and trade-mode migration, retaining the
   fallback during verification.
4. Canonicalize signal settings at persistence.
5. Publish the canonical config schema and migrate recovery DCA, then
   delisting, then AI fields.

Exit gate: old database and backup fixtures upgrade idempotently; frontend
round-trips generated schema fields; invalid booleans/settings are rejected.

### Phase 2 — Make lifecycle ownership explicit

1. Introduce the lifespan supervisor and task failure policy.
2. Add the shared provider client lifecycle.
3. Add queue primitives and observability without switching producers.
4. Route AI background producers to the queue after drain/restart tests pass.

Exit gate: critical failures stop safely; optional failures stay isolated; a
shutdown under provider stall neither hangs nor silently loses durable work.

### Phase 3 — Eliminate duplicate AI work and bound analytics

1. Extract provider, calibration, and analytics modules behind the facade.
2. Introduce typed `EntryEvaluation` and carry it through order execution.
3. Persist enforcement results exactly once and handle shadow-only evaluation.
4. Move analytics aggregation into SQLite, add indexes, revision caching, and
   query/latency budgets.

Exit gate: enforced entries perform at most one provider call, retrying
persistence does not duplicate prediction rows, and production-shaped analytics
meet the agreed budget.

### Phase 4 — Normalize trading and signal boundaries

1. Add buy/sell intent contracts.
2. Normalize CCXT execution results at the exchange adapter.
3. Move persistence to typed results.
4. Add the shared signal-entry coordinator and migrate one plugin at a time:
   ASAP, SymSignals, then WebSocket.
5. Replace SymSignals volume `DirtyFix`.

Exit gate: all plugins preserve entry semantics and reservation release;
raw exchange payloads no longer cross into orchestration/persistence.

### Phase 5 — Remove compatibility and finish operator QA

1. Remove the trade-mode runtime fallback only after migration telemetry and
   fixtures pass.
2. Remove superseded hand-written frontend config defaults/rules per migrated
   slice.
3. Remove datetime compatibility re-exports.
4. Replace corresponding source-regex tests with rendered behavior tests.
5. Fix the statistics heatmap legend and Control Center heading at 375px and
   verify the supported responsive matrix.

Exit gate: no dead compatibility path remains, the critical Playwright suite
passes at desktop and mobile viewports, and `scripts/ci.sh` is green.
